# v0.3.0 Release Readiness Checklist

This checklist helps the maintainer review what is ready, what still needs manual review, and what should happen before creating a v0.3.0 release.

v0.3.0 is not released yet. Use this checklist as a practical review tool before tagging or publishing a release.

## Documentation readiness

- [x] `docs/roadmap.md` points to the detailed v0.3.0 planning document.
- [x] `docs/v0.3.0-roadmap.md` explains the v0.3.0 documentation priorities.
- [ ] Beginner-facing docs use clear, practical wording.
- [ ] Bilingual summaries are added where useful.
- [ ] Docs avoid unsupported claims about users, stars, downloads, adoption, or impact.

## Template readiness

- [x] Main starter templates include short usage guidance.
- [ ] Template wording is consistent enough for beginner builders.
- [ ] Templates stay practical and do not become long tutorials.
- [ ] Template instructions remind users to keep AI-assisted work reviewable.

## Example readiness

- [x] Beginner examples explain who they are for.
- [x] Beginner examples explain when to use them.
- [x] Examples include practical next steps where helpful.
- [ ] Examples stay small enough to reuse or adapt.

## Checklist readiness

- [x] Beginner checklists include short context where useful.
- [x] Checklist items remain practical and action-oriented.
- [x] Related checklists link to each other where helpful.
- [x] The longer audit checklist points beginners to smaller checklists first.

## Contributor readiness

- [x] `CONTRIBUTING.md` is clear for first-time contributors.
- [x] Contributor navigation notes point to docs, templates, examples, checklists, and issues.
- [x] Issue templates are short and beginner-friendly.
- [x] Beginner contribution paths are small, focused, and reviewable.

## Release preparation

- [x] Changelog includes factual v0.3.0 preparation notes.
- [x] Draft release notes exist at [`docs/release-notes-v0.3.0.md`](release-notes-v0.3.0.md).
- [x] Maintenance log includes a concise note about the v0.3.0 documentation improvement batch.
- [ ] Open issues for v0.3.0 are reviewed.
- [ ] Completed issues are closed after review and push.
- [x] No release notes claim v0.3.0 has been published before it is actually released.

## Final manual review

- [ ] Review `git diff` before committing.
- [ ] Confirm only intended files changed.
- [ ] Check Markdown formatting.
- [ ] Check links added or updated during v0.3.0 preparation.
- [ ] Confirm no private data, API keys, tokens, or credentials were added.
- [ ] Confirm no unsupported adoption, user, star, download, or impact claims were added.
- [ ] Decide whether the repository is ready to tag and publish v0.3.0.
