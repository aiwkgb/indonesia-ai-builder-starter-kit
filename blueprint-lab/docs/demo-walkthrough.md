# SAKA Blueprint Lab Lite Demo Walkthrough

This walkthrough shows how a non-technical founder or beginner builder can use SAKA Blueprint Lab Lite before asking AI tools to code.

Use demo ideas only. Do not paste private client, finance, legal, family, or customer data into public examples.

## Demo goal

Turn a raw app/game idea into a small build-ready plan:

1. classify the project level,
2. choose the right template,
3. cut the MVP scope,
4. prepare AI prompts,
5. create a resume point.

## Demo 1 — Simple app idea

Raw idea:

```text
I want a simple app for a small service business to track customers, orders, and follow-ups.
```

### Step 1 — Route the project level

Open:

```text
blueprint-lab/templates/project-level-router.md
```

Recommended result:

```text
Project type: Software / web app
Project level: L2 MVP / Micro Product
Recommended next document: PRD Lite
Build now / validate first / park: Build a fake-data prototype first
Next 3 actions:
1. Fill PRD Lite.
2. Create a screen map.
3. Ask AI to build only the first dashboard slice.
```

### Step 2 — Fill PRD Lite

Open:

```text
blueprint-lab/templates/prd-lite.md
```

Use the example:

```text
blueprint-lab/examples/simple-app-blueprint.md
```

### Step 3 — Prepare AI prompts

Open:

```text
blueprint-lab/templates/ai-prompt-pack.md
```

Start with the MVP scope prompt, not a giant build prompt.

### Step 4 — Save a resume point

Open:

```text
blueprint-lab/templates/resume-brief.md
```

This prevents the project from becoming confusing after a break.

## Demo 2 — Mobile game idea

Raw idea:

```text
I want to make a cozy mobile idle farming game, but I only know the vibe and not the production plan.
```

Recommended result:

```text
Project type: Game
Project level: L2 MVP / Micro Product
Recommended next document: MVP Game Design Document
Build now / validate first / park: Build only the core loop prototype
Next 3 actions:
1. Define core loop.
2. Fill MVP GDD.
3. Create Godot prototype plan with one scene and three crops.
```

Use:

```text
blueprint-lab/templates/gdd-mvp.md
blueprint-lab/examples/mobile-game-blueprint.md
```

## What this demo proves

A reviewer should see that this repo helps beginners:

- avoid vague prompts,
- pick the right document,
- cut scope,
- create build phases,
- use AI tools more responsibly,
- resume work without starting from zero.

## Suggested public demo script

Use this as a short video or written post script:

```text
Many beginners open an AI coding tool with a vague prompt like: "make me an app" or "make me a game".

SAKA Blueprint Lab Lite adds a planning step before coding.

First, classify the idea.
Second, choose PRD Lite or MVP GDD.
Third, cut the scope.
Fourth, generate a prompt pack.
Fifth, save a resume brief so the project can continue later.

The goal is not heavy documentation. The goal is clearer AI-assisted execution.
```

## 60-second recording checklist

Use this when recording a future public demo video:

- [ ] Show only public GitHub pages from this repository.
- [ ] Start with the raw fictional app or game idea.
- [ ] Open the Project Level Router and explain the selected level.
- [ ] Open PRD Lite or MVP GDD and show how the idea becomes a small plan.
- [ ] Open the AI Prompt Pack and explain why prompts are staged.
- [ ] End with the Resume Brief so viewers see how work can continue later.
- [ ] Do not show private chats, dashboards, local paths, credentials, real client data, or fake metrics.
- [ ] Keep the video honest: say screenshots/video are demo assets, not traction claims.
